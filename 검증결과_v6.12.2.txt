리셀 PICK v6.12.2 로그인 유지 검증 결과

확인된 v6.12.1 문제
1. 시작 시 서명형 auth_token만 신뢰하고 /api/account/me 첫 401에서 기기 토큰을 즉시 삭제함.
2. Render 다중 워커·쿠키 저장 실패·서명키 상태의 영향을 받는 구조였음.
3. 일시적 네트워크 오류도 로그아웃으로 처리되어 로그인 화면이 다시 나타날 수 있었음.

v6.12.2 변경
1. 48바이트 임의 로그인키를 PostgreSQL persistent_login_tokens에 SHA-256 해시로 저장.
2. 원문 로그인키는 localStorage와 HttpOnly 쿠키에 1시간 저장.
3. 모든 회원 API 요청에 X-Resell-Pick-Login 헤더로 동일 로그인키 전송.
4. 새로고침·페이지 종료 후 재접속 시 DB 로그인키 한 번으로 복원.
5. 일시적 네트워크 오류에서는 1시간 이내 캐시된 로그인 상태를 즉시 해제하지 않음.
6. 서버가 명확히 login_required를 반환할 때만 기기 로그인 정보를 삭제.
7. 이전 버전 토큰을 새 로그인키로 잘못 재사용하지 않으며, 배포 후 최초 한 번 새 로그인이 필요함.
