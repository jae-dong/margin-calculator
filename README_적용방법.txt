리셀 PICK WEB v5.9.1 적용 방법

이번 버전 핵심 변경
1. 일반상품과 KREAM·POIZON 리셀 화면에서 가격표 촬영 안내 문구를 모두 삭제했습니다.
2. 상품 사진 인식 후 판매가·소싱가·매입 예정가가 자동 입력되지 않습니다. 사용자가 확인한 금액을 직접 입력합니다.
3. “현재 플랫폼 기준 장바구니” 버튼을 “장바구니 담기”로 변경했습니다.
4. 자동 키워드 경쟁·수요 분석을 교차검증 방식으로 강화했습니다.
   - 대표 키워드와 보조 키워드를 함께 조사
   - 수요·경쟁·소싱지수 외에 검색추세, 리뷰·구매 신호, 가격경쟁, 신뢰도와 근거 표시
   - 확인 시점과 보조 키워드 표시
   - 출처가 부족한 숫자는 확인값처럼 표시하지 않고 추정 범위로 구분
5. 여러 사용자의 동시 사용 안정성을 강화했습니다.
   - 회원별 저장 데이터 분리 유지
   - SQLite WAL·busy timeout·쓰기 잠금 적용
   - AI 동시 요청 제한과 Gunicorn 다중 워커·스레드 적용
   - Render 영구 디스크 경로 사용

배포 순서
1. 기존 GitHub 저장소 폴더의 파일을 이 폴더 내용으로 교체합니다.
2. GitHub Desktop에서 변경 파일을 확인합니다.
3. Summary에 “리셀 PICK v5.9.1 업데이트”를 입력합니다.
4. Commit to main을 누르고 Push origin을 누릅니다.
5. Render에서 새 배포가 완료될 때까지 기다립니다.
6. Render 환경변수 OPENAI_API_KEY와 SECRET_KEY가 설정되어 있는지 확인합니다.
7. render.yaml의 영구 디스크가 생성되었는지 확인합니다. 영구 디스크를 사용할 수 없는 요금제에서는 회원 데이터가 재배포 시 보존되지 않을 수 있습니다.
8. 휴대폰 웹앱을 완전히 종료한 뒤 다시 열거나 새로고침합니다.

검증 항목
- 상품 사진을 인식해도 판매가·소싱가·매입 예정가가 비어 있는지
- 일반상품 버튼이 “장바구니 담기”로 보이는지
- 가격표 촬영 문구가 일반상품과 리셀 화면 어디에도 없는지
- 키워드 분석 결과에 검색추세·리뷰/구매 신호·가격경쟁·신뢰도·확인시점이 표시되는지
- 서로 다른 두 계정으로 동시에 로그인했을 때 기록과 장바구니가 섞이지 않는지

주의
현재 구조는 소규모 베타 운영을 위한 동시 사용 안정화 버전입니다. 수백 명 이상의 정식 유료 운영 전에는 PostgreSQL 같은 상용 데이터베이스로 전환하는 것이 안전합니다.
