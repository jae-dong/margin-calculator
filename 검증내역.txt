리셀 PICK v6.11.6 검증 내역

[원본 정밀검사에서 확인한 핵심 원인]
1. 기존 로그인 유지는 Flask 세션 쿠키와 서명 토큰에 지나치게 의존했습니다.
2. 모바일 브라우저가 쿠키·서명 토큰을 잃으면 DB의 기존 세션을 다시 찾을 독립 장치키가 없었습니다.
3. 앱 시작 시 로그인 복원이 끝나기 전에 다른 API가 401을 반환하면 로그인창을 다시 띄우는 경쟁 조건이 있었습니다.
4. 모바일 로그인창이 화면 아래 정렬이라 키보드가 열릴 때 입력영역과 버튼이 겹쳤습니다.

[이번 버전 자동검사 — 통과]
- Python py_compile 문법 검사
- HTML 내부 JavaScript Node 문법 검사
- HTML 중복 id 검사
- 화면·서버·서비스워커·manifest·version.json 버전 일치 검사
- 장치키 localStorage 저장 및 메모리 초기화 후 재복원 단위검사
- 인증·복원 토큰을 제거한 상태에서 장치키만으로 복원 요청 헤더와 본문 생성 단위검사
- 실제 app.py에서 추출한 장치 세션 생성·조회·1시간 만료·폐기 함수 SQLite 단위검사
- PostgreSQL·SQLite device_token_hash 마이그레이션 구문 검사
- 로그인·회원가입·내 계정·heartbeat·복원 응답의 device_token 발급 경로 검사
- 로그아웃 시 장치 세션 폐기 및 장치 쿠키 삭제 경로 검사
- ZIP 파일 CRC 무결성 검사

[배포 후 실기기 확인이 필요한 항목]
- 사용자님의 실제 Render PostgreSQL과 삼성 인터넷/PWA 환경에서 새로고침 유지
- 뒤로가기로 웹 종료 후 1~5분 내 재실행 유지
- 모바일 키보드 표시 시 로그인창 최상단 배치

코드 자동검사와 단위검사는 완료했지만 실제 Render 계정과 사용자 휴대폰에는 접근할 수 없으므로, 위 3개 항목은 배포 후 실기기 최종 확인이 필요합니다.
